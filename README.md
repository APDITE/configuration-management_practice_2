# Визуализатор графа зависимостей Maven (вариант 17)

Практическая работа № 2 по дисциплине «Конфигурационное управление».

## Общее описание

Консольное приложение (CLI) на Python 3 для построения и визуализации
графа зависимостей пакетов Java (Maven). Готовые менеджеры пакетов и
библиотеки для получения зависимостей не используются.

Текущее состояние — **этап 3**: основные операции. Приложение строит
граф зависимостей заданного пакета с учётом транзитивности обходом в
глубину (DFS) без рекурсии, находит циклические зависимости и выводит
граф на экран. Источник данных — реальный репозиторий Maven (файлы
POM) или тестовый репозиторий из текстового файла.

Сторонние зависимости не требуются — только стандартная библиотека
Python 3.8+: `argparse` (параметры), `urllib.request` (загрузка файлов
по HTTP), `xml.etree.ElementTree` (разбор XML). Логика получения
зависимостей (наследование, свойства, dependencyManagement) реализована
самостоятельно, без Maven и библиотек для работы с ним.

## Структура репозитория

```
src/
  depviz.py     точка входа: выбор репозитория, построение и вывод графа
  graph.py      граф зависимостей: DFS без рекурсии, поиск циклов
  config.py     параметры командной строки и их проверка
  pom.py        разбор файла POM: координаты, свойства, зависимости
  maven.py      загрузка POM из репозитория Maven, зависимости пакета
  testrepo.py   тестовый репозиторий из текстового файла
  errors.py     общее исключение RepositoryError
repos/          тестовые репозитории для режима test
scripts/        скрипты ОС для демонстрации работы
tests/          модульные тесты (unittest)
  fixtures/maven/  тестовый репозиторий Maven для локального сервера
  maven_server.py  локальный HTTP-сервер для тестов без сети
run.sh          запуск приложения и тестов
```

## Настройки

Все параметры задаются опциями командной строки:

- `-p`, `--package NAME` — имя анализируемого пакета (обязательный):
  - в режиме `remote` — координаты Maven `groupId:artifactId:version`,
    например `org.slf4j:slf4j-api:2.0.13`;
  - в режиме `test` — большие латинские буквы, например `A`.
- `-r`, `--repo URL_OR_PATH` — где искать пакеты (обязательный):
  - в режиме `remote` — URL-адрес Maven-репозитория (`http` или
    `https`), например `https://repo1.maven.org/maven2`;
  - в режиме `test` — путь к файлу тестового репозитория.
- `-m`, `--mode {remote,test}` — режим работы с тестовым репозиторием:
  `remote` (по умолчанию) — реальный репозиторий по URL, `test` —
  тестовый репозиторий из файла.
- `-h`, `--help` — справка по параметрам.

Тестовый репозиторий — текстовый файл, в каждой строке которого указан
пакет и через двоеточие его прямые зависимости через пробел (пример —
`repos/simple.txt`). Пустые строки пропускаются; пакет, который
встречается только среди зависимостей, считается пакетом без
зависимостей.

```
A: B C
B: D
C: D
D:
```

## Функции

### Построение графа зависимостей

Граф строится обходом в глубину (DFS) **без рекурсии**: вместо стека
вызовов используется явный стек (список) пакетов, ожидающих обработки.

1. В стек помещается заданный пакет.
2. Пока стек не пуст, из него извлекается пакет. Если пакет уже есть в
   графе, он пропускается; иначе запрашиваются его прямые зависимости,
   пакет добавляется в граф, а ещё не посещённые зависимости
   помещаются в стек (в обратном порядке, чтобы первой обрабатывалась
   первая зависимость).

Каждый пакет запрашивается у репозитория ровно один раз, поэтому
общие зависимости не дублируются, а **циклические зависимости** не
приводят к зацикливанию. Глубина графа не ограничена пределом рекурсии
Python (в тестах обходится цепочка из 10000 пакетов).

Циклы находятся вторым обходом в глубину, тоже без рекурсии: пакеты на
текущем пути обхода помечаются «серыми», и ребро в серый пакет
(обратное ребро) означает цикл.

### Зависимости пакета Maven (режим `remote`)

1. По координатам `groupId:artifactId:version` строится адрес файла
   `{repo}/{groupId с «/» вместо «.»}/{artifactId}/{version}/`
   `{artifactId}-{version}.pom`, файл скачивается по HTTP(S).
2. Загружается цепочка родительских POM (`<parent>`) до корня.
3. Свойства `<properties>` объединяются от предков к потомку; значения
   `${имя}` подставляются, включая встроенные `${project.version}`,
   `${project.groupId}`, `${project.parent.version}` и др.
4. Зависимости `<dependencies>` и `<dependencyManagement>` наследуются
   от родителей (запись потомка важнее записи предка).
5. Записи `dependencyManagement` со `scope=import` и `type=pom`
   импортируют управляемые версии из BOM (явно объявленные записи
   важнее импортированных).
6. Если у зависимости не указаны `version` или `scope`, они берутся из
   `dependencyManagement`; scope по умолчанию — `compile`.
7. В граф попадают только зависимости, которые Maven передаёт тем, кто
   использует пакет: обязательные (не `optional`) со scope `compile`
   или `runtime`. Зависимости `test`, `provided`, `system` и
   необязательные нужны только для сборки самого пакета и в граф не
   включаются — ни для заданного пакета, ни для транзитивных.

### Зависимости пакета (режим `test`)

Зависимости пакета — имена из его строки в файле тестового
репозитория. Пакет, у которого нет своей строки, не имеет зависимостей.

### Вывод

По строке на каждый пакет графа в порядке обхода в глубину:
`пакет -> зависимость, зависимость, ...`; пакет без зависимостей
выводится отдельной строкой. Затем выводятся найденные циклы:
`cycle: A -> B -> C -> A`. Код завершения — 0.

Если не удалось загрузить транзитивную зависимость (например, её нет
в репозитории), в stderr выводится предупреждение
`depviz: warning: <пакет>: <причина>`, пакет помечается
`(not resolved)` и считается пакетом без зависимостей, а граф
строится дальше. Ошибка загрузки заданного пакета прерывает работу
(код завершения 1).

### Обработка ошибок параметров

При ошибке в параметрах выводятся краткая справка и причина, код
завершения — 2.

- `--package`:
  - не указан: `the following arguments are required: -p/--package`;
  - пустой: `--package: empty package name`;
  - в режиме `remote` не в формате Maven (три непустые части через
    двоеточие, каждая начинается с буквы или цифры):
    `--package: 'slf4j-api': expected groupId:artifactId:version`;
  - в режиме `test` не из больших латинских букв:
    `--package: 'a': in test mode the package name must consist of
    capital Latin letters`.
- `--repo`:
  - не указан: `the following arguments are required: -r/--repo`;
  - пустой: `--repo: empty repository location`;
  - в режиме `remote` не http(s) URL:
    `--repo: 'ftp://...': expected an http(s) URL of a Maven repository`;
  - в режиме `remote` URL содержит пробельные символы:
    `--repo: '...': URL must not contain whitespace`;
  - в режиме `test` файл не найден, это каталог или нет прав на
    чтение: `no such test repository file`, `not a file`,
    `permission denied`.
- `--mode`: недопустимое значение —
  `argument -m/--mode: invalid choice: 'prod' (choose from 'remote',
  'test')`.
- Неизвестный параметр: `unrecognized arguments: --depth 3`.
- Сокращённые имена параметров (например, `--pack`) не принимаются.

### Ошибки получения зависимостей

Выводится `depviz: error: <причина>`, код завершения — 1.

- режим `remote`:
  - пакета нет в репозитории (HTTP 404):
    `package not found in repository: <URL файла POM>`;
  - нет родительского POM: `cannot load parent POM <координаты> of ...`;
  - другая ошибка HTTP: `HTTP error <код> <причина>: <URL>`;
  - репозиторий недоступен: `cannot reach repository: <причина>`;
  - некорректный XML: `<URL>: malformed POM: <подробности>`;
  - циклическая цепочка родителей: `cyclic parent POM: <координаты>`;
- режим `test`:
  - пакета нет в файле: `package 'Z' not found in test repository`;
  - строка неверного формата:
    `<файл>:<строка>: expected 'NAME: DEPENDENCY ...' with capital
    Latin letters`;
  - пакет описан дважды: `package 'A' is already defined`;
  - файл не читается как текст UTF-8: `cannot read test repository`.

Циклический импорт BOM и циклические ссылки свойств не приводят к
зацикливанию: повторный импорт пропускается, нераскрытое свойство
выводится как есть (например, `${a}`).

## Сборка и запуск

Сборка не требуется.

```sh
./run.sh -p org.slf4j:slf4j-api:2.0.13 -r https://repo1.maven.org/maven2
./run.sh -p A -r repos/simple.txt -m test
./run.sh test                     # запуск тестов
```

Без `run.sh`:

```sh
python3 src/depviz.py -p A -r repos/simple.txt -m test
python3 -m unittest discover -s tests -t . -v
```

Скрипты ОС (`scripts/`):

- `test_graph.sh` — граф зависимостей для тестовых репозиториев
  (ромб, циклы, петля, недостижимые пакеты) и для пакетов из Maven
  Central (нужен интернет);
- `test_errors.sh` — ошибки каждого параметра, неизвестный параметр и
  ошибки получения зависимостей (ошибка `permission denied` не
  воспроизводится при запуске от root).

Модульные тесты не обращаются к сети: для режима `remote` они
запускают локальный HTTP-сервер с файлами из `tests/fixtures/maven`.
Его же можно запустить вручную:

```sh
python3 -m http.server 8000 -d tests/fixtures/maven
./run.sh -p org.example:lib:1.0 -r http://localhost:8000
```

Тестовые репозитории (`repos/`):

- `simple.txt` — общая зависимость (ромб), циклов нет;
- `cycle.txt` — цикл через заданный пакет `A -> B -> C -> A`;
- `self.txt` — пакет зависит сам от себя;
- `complex.txt` — несколько циклов, общие зависимости и пакеты `X`,
  `Y`, недостижимые из `A`;
- `broken.txt` — файл с ошибкой формата.

## Примеры использования

Реальный репозиторий Maven (Maven Central):

```sh
./run.sh -p com.google.guava:guava:33.2.1-jre \
    -r https://repo1.maven.org/maven2
```

Тестовый репозиторий Maven из `tests/fixtures/maven`: из шести прямых
зависимостей `lib` в граф попадают только `compile` и `runtime`;
пакета `ghost` нет в репозитории (URL в предупреждении сокращён):

```
$ ./run.sh -p org.example:lib:1.0 -r http://localhost:8000
depviz: warning: org.example:ghost:1.0: package not found in repository: http://localhost:8000/...
org.example:lib:1.0 -> org.example:core:1.2.3, org.example:rt:1.0, org.example:ghost:1.0
org.example:core:1.2.3
org.example:rt:1.0 -> org.example:core:1.2.3
org.example:ghost:1.0 (not resolved)
```

Общая зависимость `D` выводится один раз:

```
$ ./run.sh -p A -r repos/simple.txt -m test
A -> B, C
B -> D
D
C -> D
```

Циклические зависимости:

```
$ ./run.sh -p A -r repos/cycle.txt -m test
A -> B
B -> C
C -> A, D
D
cycle: A -> B -> C -> A
$ ./run.sh -p A -r repos/complex.txt -m test
A -> B, C
B -> D, E
D -> G
G
E -> G, H
H -> B
C -> E, F
F -> C
cycle: B -> E -> H -> B
cycle: C -> F -> C
```

Ошибки:

```
$ ./run.sh -p slf4j-api -r https://repo1.maven.org/maven2
usage: depviz [-h] -p NAME -r URL_OR_PATH [-m {remote,test}]
depviz: error: --package: 'slf4j-api': expected groupId:artifactId:version
$ ./run.sh -p org.example:nope:1.0 -r http://localhost:8000
depviz: error: package not found in repository: http://localhost:8000/org/example/nope/1.0/nope-1.0.pom
$ ./run.sh -p A -r repos/broken.txt -m test
depviz: error: repos/broken.txt:2: expected 'NAME: DEPENDENCY ...' with capital Latin letters
```
